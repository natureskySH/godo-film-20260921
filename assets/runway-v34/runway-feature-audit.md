# Runway 기능·비용 교차 검토 — GODO V34

확인일: 2026-09-28. 공식 Help Center·Academy와 현재 연결된 Runway 플러그인의 도구 명세를 대조했다. 생성·워크플로 실행·과금 동작은 하지 않았다. 아래의 ‘적합성’은 프로젝트에 대한 제작 판단이며 모델 성공 보장이 아니다.

> 최종 제작안은 동작 전후 정지와 편집 여유를 확보하기 위해 **5초 25크레딧 시험**을 우선 제안한다. 아래 2초 20크레딧 안은 최소 총액 비교용 대안이며 두 안 모두 미승인이다.

## 제작 결정

- **한 번에 전편을 생성하지 않는다.** 시작 이미지와 단일 동작을 지정한 독립 숏을 만들고, 선택한 구간을 편집한다. 6개 숏의 의도·입출력 상태·화면 방향·컷 지점은 먼저 고정한다.
- 첫 테스트 후보는 얼굴이 없는 **S02 매듭 당김**이다. 이미 매듭이 형성된 상태에서 양손이 양쪽 끝을 짧고 단단하게 한 번 당기고 정지하는 동작으로 제한한다. 새로운 매듭을 만드는 복잡한 손가락 동작까지 넣지 않는다.
- S03·S04가 짧다는 것은 **화면에 머무는 시간을 줄인다**는 뜻으로 구현한다. 손을 빨리 휘갈기거나 임의 배속하는 지시로 바꾸지 않는다.
- S04→S05는 같은 파란색 영역·같은 손잡이·같은 진행 방향을 유지한 더 가까운 구도로 연결한다. 실제 접촉 위치와 선/색의 변화를 프레임 단위로 검수한다.
- S06 엔딩의 중앙 확대와 암전은 확정 작품 이미지에 **로컬 편집의 위치·스케일·노출 키프레임**으로 주는 편이 정확하다. 작품·KOREA 글자를 재생성하지 않으면서 사용자 요청을 충족하고 생성 크레딧을 아낀다. 영상 생성이 꼭 필요한 부분과 편집만으로 정확히 되는 부분을 구분하는 판단이다.

## 최소 비용: 초당 가격과 1회 총액은 다르다

동일 720p 시작 이미지 1장 입력을 전제로 한 산술 추정이다. 연결된 플러그인 명세의 지원 길이를 사용했다. 마지막 실행 전 실제 설정과 비용을 다시 확인하고 별도 승인받아야 한다.

| 선택지 | 초당 가격 | 최소 길이 | 최소 1회 예상 | 이번 테스트 적합성 |
|---|---:|---:|---:|---|
| WAN 3.0 | 10 | 2초 | **20** | 2초 안에 한 번 당기고 멈추는 동작의 가장 저렴한 실용 후보 |
| Gen-4.5 | 12 | 2초 | **24** | 고급 모델도 아주 짧은 숏이면 Turbo 최소 총액보다 낮음 |
| Gen-4 Turbo | 5 | 5초 | **25** | 초당 최저. 정지→당김→정지 여유를 5초에 배치해 편집하기 유리 |
| Grok Imagine 1.5 | 16 + 입력 이미지당 1 | 1초 | **17** | 명목 최저이나 1초는 동작·종료 안정성 확인이 부족. 2초면 33 |

가격은 [Runway 공식 모델 요금표](https://academy.runwayml.com/models-pricing), [Gen-4 사양](https://help.runwayml.com/hc/en-us/articles/37327109429011-Creating-with-Gen-4-Video), [Gen-4.5 사양](https://help.runwayml.com/hc/en-us/articles/46974685288467-Creating-with-Gen-4-5), [Grok 1.5 사양](https://help.runwayml.com/hc/en-us/articles/53995376768147-Creating-with-Grok-Imagine-1-5)에 근거한다. WAN의 2초 최소 길이와 Grok의 1초 최소 길이는 현재 `runway_generate_video` 명세에서 확인했다.

**권장 승인 단위:** ‘S02 시작 이미지 1장 → WAN 3.0, 720p, 16:9, 2초, 오디오 끔, 결과 1개, 예상 20크레딧, 자동 재시도 없음.’ 단, 시작 이미지의 손과 끈이 제대로 분리되고 이미 잡힌 상태여야 한다. 안정된 동작 전후 여유를 더 중요하게 선택하면 Turbo 5초 25크레딧이 대안이다. ‘전 모델 중 가장 저렴하다’고 단정하지 않는다.

완료된 결과가 기대와 달라도 자동 환급되는 것은 아니다. 실제 생성 오류로 종료된 경우와 품질 불만족은 구분되므로, 불합격 시 다음 시도를 자동 실행하지 않는다. [환급 기준](https://help.runwayml.com/hc/en-us/articles/34266159290003-Can-I-have-credits-refunded)

## Workflows: 비용을 통제하는 운용

1. 승인된 이미지 입력 → 승인된 텍스트 입력 → 숏별 영상 노드의 최소 구조로 만든다. 기존 그래프를 조회하고 지원 노드 형식을 복사해 수정·검증한다.
2. 자동 프롬프트 향상 LLM 노드도 유료다. 이번에는 이미 작성된 프롬프트를 직접 넣어 중복 과금을 피한다.
3. 시험할 **노드만 실행**한다. 플러그인 `node_ids` 선택 실행은 상위 노드가 이미 성공해야 한다. 매번 Run all 하지 않는다.
4. 통과한 출력은 Lock node로 동결하여 재실행 때 다시 생성하지 않는다. 입력·프롬프트·모델·설정·task ID·실제 비용을 저장한다.
5. Seed(난수 시작값)는 지원되는 모델/노드에서만 설정한다. 같은 seed가 비슷한 움직임을 유도할 수 있지만 인물·손·작품을 완벽히 고정하는 잠금장치가 아니다. 직접 `generate_video`에는 seed 매개변수가 노출되어 있지 않다.
6. `validate_workflow_graph(estimate_cost:true)`로 실행 전 그래프 비용을 조회할 수 있다. 그래프는 `get_workflow`로 얻은 실제 형식에서 작성하며 임의 JSON을 발명하지 않는다.
7. 사용자에게 입력·절차·모델·개수·길이·해상도·비용 상한을 보고한 다음 명시적 승인 범위만 실행한다. 오류라도 승인 없이 자동 모델 변경/재시도하지 않는다.

Workflows는 미디어 노드와 LLM 노드가 과금되며 일부 utility도 유료다. 선택 실행·출력 잠금과 seed 설정은 [공식 Workflows 안내](https://help.runwayml.com/hc/en-us/articles/45763528999699-Introduction-to-Workflows)에 설명되어 있다. 플러그인 MCP는 **Explore Mode를 지원하지 않고 계정 크레딧을 사용**한다. [MCP 안내](https://help.runwayml.com/hc/en-us/articles/51931843164691-Connecting-to-Runway-MCP)

## 남겨야 할 불확실성

- 공식 Gen-4.5 Help Center는 720p, 플러그인 표는 최대1080p로 표시가 다르다. 이번 테스트는 요청된720p이므로 문제없지만 1080p를 약속하려면 실행 직전 지원 여부를 추가 확인한다.
- 웹 Apps 기능이 모두 플러그인 도구로 노출된 것은 아니다. Apps 공식 문서의 ‘API 제공 안 함’과 일부 기능을 별도 MCP 도구로 실행하는 것은 구분해야 한다. Motion Sketch/Act-Two의 직접 호출 가능성을 검증 없이 약속하지 않는다.
- 정확한 손동작·선이 생기는 위치·얼굴 동일성은 비용이나 기능 수로 보증할 수 없다. 짧은 유료 시험과 프레임 단위 합격 기준이 필요하다.
- 눈에 보이는 Gemini 별 모양 마크와 보이지 않는 출처 표식은 별개다. 이번 에셋에서 가시 마크를 파일별로 확인하는 작업과 ‘모든 출처 표식을 제거했다’는 주장은 구분해야 한다. 본 조사는 이미지/영상 파일 워터마크 검수 결과를 대신하지 않는다.

**‘모든 기능 사용’이 목표가 아니라, 필요한 기능의 지원·가격·제약을 빠짐없이 확인하고 정확한 결과에 도움이 되는 기능만 선택하는 것이 목표다.**
